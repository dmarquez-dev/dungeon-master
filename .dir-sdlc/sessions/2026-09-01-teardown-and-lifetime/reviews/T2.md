## Advisory findings

1. **`ObjectCatalogueScope.ShippedPackKinds` duplicates `pack.json` as a hand-maintained literal** (`src/DungeonMaster.App.Tests/Graphics/FakeAssetSource.cs`, the 29-entry list). Correct today — verified this session by set comparison — but adding a kind to the pack will not fail any test. The drift is silent. Deriving the list from the pack manifest, or adding one fact comparing the two, would close it.
2. **`ObjectAssetCatalogue` is process-wide and `ObjectCatalogueScope` mutates it.** The class remarks note that all such facts must live in one class because xunit parallelizes across classes. That constraint is documented but not enforced — a future test class touching the catalogue would flake. No other file under `src/DungeonMaster.App.Tests` references `ObjectAssetCatalogue` today, so nothing is at risk now.
3. **The `InternalsVisibleTo` escalation stands on its own merits.** `ObjectAssetCatalogue.SetPaths` is `internal`, its only caller is `ObjectPaletteView.xaml.cs`, and there is no `InternalsVisibleTo` for `DungeonMaster.App.Tests`, so reflection is currently the only host-free route. Granting it — as `App.Core`, `Application` and `Domain` each already do for `DungeonMaster.Tests` — would remove the reflection, but that file is outside T2's ownership. Raised as escalation **E4**.
