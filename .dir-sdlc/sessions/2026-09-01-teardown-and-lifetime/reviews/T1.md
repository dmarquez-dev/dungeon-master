## Advisory findings

1. **A test that cannot fail.** `EveryExceptionTheHostMarksHandledIsRecordedWithATypeAndAMessage` (`src/DungeonMaster.App.Tests/Hosting/MauiHostFixtureTests.cs`) puts both assertions inside `foreach (var exception in handled)`, so with today's empty collection it executes no assertion at all — it is a diagnostic printer, not a guard. It is **not** the evidence criterion 7 rests on (the zero comes from the fixture's recorded count, corroborated by the `Handled = true` removal), but a consumer reading the test name will over-trust it. An `Assert.Empty`-style statement of the measured expectation would make the name true.
2. **The recorder's capture path is unexercised.** No exception was ever injected onto the WinUI dispatcher to watch it land in `HandledExceptions`. The removal experiment establishes that none occurs, which is why criterion 7 is met — but T3, T4 and T5 will rely on this collection for diagnosability of a startup regression, and nothing has shown it fires.
3. **Temp-database accumulation is larger than reported.** `Dispose` deletes per-run directories best-effort; `ls` of `%TEMP%\DungeonMaster.App.Tests` shows **7**, not the report's "two survived". Harmless and outside every criterion, but the report's count is stale.
4. **An undescribed error case.** `CreateMauiApp` now skips folder creation when `Path.GetDirectoryName` yields null/empty rather than surfacing through the existing `catch`. Strictly safer than the `ArgumentNullException` the unguarded call would throw — that type is outside the existing filter — and default behaviour is unchanged. Noted only because the contract's error-case table does not describe it.
