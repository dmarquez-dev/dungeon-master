## Contradicts

### C1 — Criterion 2's prescribed arrangement cannot produce the evidence it asks for

`manifest.json`, T5 acceptance criterion 2, states the test "sets `page.Handler = null`, and asserts `IsDisposed` is true". **Reproduced:** with the correct implementation in place and only that assignment, the test **fails** (`Failed: 1, Passed: 0`) — MAUI's `Element` handler setter returns early when assigned the value it already holds, so a DI-resolved page whose handler is already null raises no `OnHandlerChanged` at all. What is true instead: a non-null handler must be connected first, then nulled. The `StubElementHandler` — which must implement `IViewHandler`, not `IElementHandler`, because `VisualElement.Handler` is typed `IViewHandler` — is a **necessary addition, not scope creep**.

This moves scoped work: `MASTER-013`'s page half is the closing evidence for that master entry, and a session that followed the criterion literally would have shipped either a red test or, had the implementation been absent, a test proving nothing.

| Rank | Option | Rationale | Evidence |
|---|---|---|---|
| 1 | Amend criterion 2 to require connecting a minimal `IViewHandler` and then nulling it, and to require the connect step be shown load-bearing | It is the arrangement actually shipped and independently reproduced here, so the criterion would describe reality with no rework | `repo` — `DungeonDetailPageTeardownTests.cs` plus the reproduction above |
| 2 | Leave criterion 2 as written and record the deviation as an accepted amendment in the session's artifacts | The manifest is a frozen record of intent; annotating it preserves the audit trail without rewriting a closed criterion | `judgment` |
| 3 | Generalise the criterion to "trigger a real handler disconnect by whatever arrangement the framework requires", naming no sequence | Avoids re-freezing a framework detail that may change across MAUI versions | `judgment` |

### C2 — Criterion 7's prescribed injection does not discriminate

`manifest.json`, T5 acceptance criterion 7, states "make `TouchEnded()` skip clearing `_active`, quote the failure". **Reproduced:** under that exact injection the criterion's own named released-press test stays **green** (`Failed: 1, Passed: 5, Total: 6`; the sole failure is the added re-armed-timer test). `TouchEnded()` also calls `_timer.Stop()`, and `FakeLongPressTimer.Tick()` returns early when `!IsRunning`, so the `_active` guard is never reached — **the same trap T4 hit**.

This moves scoped work: the injection is the criterion's proof of falsifiability, and as written it would have certified a test that cannot fail on its own account.

## Advisory findings

1. **`CapturedSubscription<T>.Attach()` assigns `_capturedTarget` *after* `_subscribe(target)` returns** — the mirror of the deliberate clear-before-unsubscribe ordering in `Detach()`. A throwing subscribe would leave the target subscribed but uncaptured, and a later `Detach()` would unsubscribe nothing. Not reachable through the real page (`+=` on a `FrameworkElement` event does not throw) and no criterion covers it.
2. **The threading requirement is documented but unenforced.** The class-level "Single-threaded by design" note is the only statement of it; a consumer reaching for this type from a background thread has nothing stopping it.
3. **`DungeonDetailPage.xaml.cs` references `CapturedSubscription<T>` fully qualified in three places** to avoid an unused-using error on the macCatalyst TFM. A `#if WINDOWS`-guarded `using` would read better and compiles equally clean, but the current form is correct and the diff is smaller.
