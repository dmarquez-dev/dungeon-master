## The vacuity question -- the substance of this task

The reviewer's judgment, which went past its brief in the way this project has now seen for seven
sessions running: **no surviving or converted test is vacuous, but T1's four injections prove less
than their count suggests.**

All four injections mutated **test** code, not production code -- T1 correctly declined to touch
`PlacedObject.cs` / `FloorObjectMethods.cs`, which are T2's ownership set. A test-side injection
proves an assertion *reads the value it names and compares it*, which retires the
"assertion present but inert" failure mode. It does **not** prove the assertion would catch the
production regression the test exists to prevent. The reviewer closed that gap by inspection rather
than by a sixth run, on the two that matter:

- **A4's sole cover works.** `PlacedObject.cs:48` is `Scale = scale;` and `:67` initialises to
  `ObjectScale.Default`. Delete `:48` and `Constructor_WithCustomScale_SetsScale` expects 2.0f, gets
  1.0f -> red. The sibling vacuity A4 predicts is real -- `Constructor_SetsAllProperties:27` can no
  longer catch it -- and A4's designated cover holds.
- **A8's moved assertion works.** `KindGuardRunsBeforeTheScaleRejection` passes `None` *with an
  out-of-range scale*. Remove the guard's `None` condition and the scale guard throws instead: same
  exception type, but `ParamName` becomes `"scale"`, so the test goes red on both assertions.

**Over-deletion, the gap the dispatch flagged as unprotected by any T1 criterion: clear.** The
reviewer read all 103 deleted lines. The signature census above is the measurement, and every deleted
non-signature line is either an `ObjectRotation.None);` argument line replaced by the two-line
rotation-plus-scale form, or a line inside one of A3's five named method bodies.

## Advisory findings

Reviewers attach remediation options to blocking findings only, so these carry none.

**Advisory 1 -- the converted `AddPlacedObject_ReturnsObjectWithGivenKindPositionRotationAndScale`
has a non-discriminating `Scale` assertion.** `DungeonAggregateTests.cs:451` passes
`ObjectScale.Default` and asserts `ObjectScale.Default`; because `PlacedObject.cs:67` initialises
`Scale` to that same value, the assertion would still pass if `Dungeon.AddPlacedObject` dropped the
scale argument entirely. Passing `2.0f` instead would have made it discriminating and the name's
`AndScale` fully earned, at no cost.

**Verified by the orchestrator, and the criterion is partly at fault.** A2's letter requires
`ObjectScale.Default` be the argument, so the stronger form was foreclosed by the criterion itself
rather than missed by the implementer. The reviewer also probed for a real coverage hole and measured
that there is none: non-default scale forwarding is covered at two levels --
`AddPlacedObjectCommandHandlerTests.HandleAsync_WithCustomScale_StoresScaleOnObject:160-181` passes
`Scale: 2.0f` and asserts 2.0f through `AddPlacedObjectCommandHandler.cs:24-29`, and
`DungeonWriteRepositoryTests.LoadAsync_RoundTripsFloorObjectPositionsUnchanged:202-208` passes `1.5f`
and asserts it at `:224`. The weak assertion is **redundant, not load-bearing.**

**Advisory 2 -- no test now asserts `ObjectKind.None` is rejected when the scale is valid.** The
deleted `FourParameterConstructor_WithNoneKind_Throws` did, via the implicit default scale; the sole
survivor pairs `None` with `ObjectScale.Max * 2f`. Coverage still holds -- the reviewer showed the
survivor discriminates, because removing the `None` condition changes `ParamName` to `"scale"` -- but
the population exercised is narrower than before. A `None` plus `ObjectScale.Default` case would
restore it in three lines.

**Advisory 3 -- A3's stated rationale for one deletion is imprecise.** A3 describes
`UpdateObject_WithoutScaleOnUnknownId_ReturnsNotFound` as "a literal duplicate of
`UpdateObject_UnknownId_ReturnsNotFound` at `:98` once converted". The reviewer checked
`git show b39a65d:.../FloorObjectMethodsTests.cs` and found the survivor was **already** the
four-argument form passing `1.0f` at `b39a65d:97-107` -- it needed no conversion, and correctly does
not appear in A1's list of 13.

**The orchestrator's correction to the reviewer, recorded because taking it at face value would
overstate the defect.** The reviewer read "once converted" as applying to the *survivor*, which
cannot be right. Read as applying to the *deleted* test -- the natural reading -- the claim holds:
converted with `ObjectScale.Default`, which **is** `1.0f`, the deleted test would differ from the
survivor in token only, not in value. So the rationale is **loose rather than false**: "literal"
overstates a token difference, and the phrase invites the reviewer's misreading. The criterion's
requirement is met either way and the deletion loses nothing. This is separate from the
`measurement.md` section 5.2 error, which concerns the *other* deletion.
