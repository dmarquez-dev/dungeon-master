## The finding T3 and T5 read

**The three non-finite values do not behave alike.** Reproduced independently by the reviewer, and
established at the storage layer, which T1's own evidence did not reach:

| Value | Observed | Established by |
|---|---|---|
| `float.NaN` | **Throws on save.** `DbUpdateException` wrapping `InvalidOperationException("Cannot store 'NaN' values.")`. Nothing written; reload unreachable. All three NaN cases (both coordinates, `X` only, `Y` only) throw | T1's test; reviewer-reproduced |
| `float.PositiveInfinity` | **Round-trips intact.** Saved, reloaded as `Infinity` | reviewer read the raw column: `SELECT typeof(Position_X), Position_X, Position_Y FROM PlacedObjects` -> `type=real X=∞ Y=∞` |
| `float.NegativeInfinity` | **Round-trips intact.** Saved, reloaded as `-Infinity` | same query -> `X=-∞ Y=-∞`, plus mixed cases `X=∞ Y=7.25` and `X=12.5 Y=-∞` |

**The persistence layer is not a guard.** It stops one of three non-finite cases, and does so as a
commit-time exception rather than at the boundary that accepted the value. Not `NULL`, not clamped, not a
text sentinel — `typeof()` is `real`.

**The rejection is correctly attributed, and the reviewer established it on two independent legs:**

1. The message is the resource `Microsoft.Data.Sqlite.Properties.Resources.CannotStoreNaN`, located in the
   managed provider the tests bind against —
   `~/.nuget/packages/microsoft.data.sqlite.core/10.0.11/lib/net8.0/Microsoft.Data.Sqlite.dll` and its
   companion `.xml`. It is **not** a SQLite native error.
2. The exception **type** is itself the discriminator and the test asserts it: a `REAL NOT NULL` violation
   surfaces as `SqliteException` with a constraint code, never as `InvalidOperationException`.

Schema characterisation confirmed: `Position_X = table.Column<float>(type: "REAL", nullable: false)` at
`src/DungeonMaster.Infrastructure/Migrations/20260805014736_InitialCreate.cs:84`.

## Advisory findings

Advisories carry **no remediation options** — the reviewer attaches options to blocking findings only.

**A1. `"the column type ... play[s] no part in it"` at `:16` is one step broader than what was shown.**
`IsRequired()` genuinely plays no part, and that half is solid. But the `REAL` mapping is precisely *why*
EF attempts a double parameter bind, and it is that bind which refuses NaN; a mapping converting the
coordinate to TEXT would store NaN without complaint. **The claim that survives the evidence is narrower:**
*the rejection is the ADO provider refusing to bind a NaN parameter — not a SQLite constraint and not
`IsRequired()`.* Flagged because the audit register's wording outlives the session, and T5 would otherwise
inherit the broader sentence.

> **Orchestrator action taken:** the narrowed wording, not T1's broader sentence, is handed to T5 at
> dispatch. T1's file is not edited — an advisory never triggers a revision round.

**A2. `"before any SQL is executed"` at `:16` is true but easy to misread.** The statement is prepared
first; what never happens is its *execution*. Accurate as written, imprecise to a fast reader.

**A3. The verbatim message assertion at `:59` couples the test to a `Microsoft.Data.Sqlite` resource
string.** T1 chose this deliberately and the reviewer would not change it — it is what makes the NaN test
discriminate on the *reason* rather than merely on a throw, which defeats the broken-fixture failure mode.
Flagged only so the coupling is a known cost: a reworded or localized resource breaks it, and the fix is a
one-line message update rather than a re-investigation.

**A4. T1's warning about T5's register wording is correct, and it is NOT a `contradicts` finding.** The
reviewer checked: `grep -rn -i "non-finite\|NaN\|finiteness\|Infinity" docs/audit/00-master-index.md`
returns no existing row making the uniform claim, so nothing already written has been falsified — the row
T5 will write simply does not exist yet. **The register must not say "SQLite rejects non-finite floats."**
It rejects exactly one of three, from the ADO layer, and stores both infinities intact.
