## Advisory findings

**1 — contract gap. The explicit `MutationOutcome.None` switch arm is behaviourally decorative and no test
protects it.** `MutationOutcomeExtensions.cs:77-82`. The reviewer ran a **third injection the spec did not
ask for**, deleting the `None` arm outright and leaving only `_`: all 11 `MutationOutcome` tests stayed green,
including `ToResult_WithNone_Throws`. The arm is load-bearing only for contract C3's *separate-removability*
property, not for observable behaviour. Injection A is nonetheless genuine discrimination rather than a
re-proof of the catch-all — it reddens only the `None` test while the unrecognised test stays green, which the
catch-all alone cannot produce. **Residual risk:** a future maintainer can delete the arm with no test going
red, after which injection A is no longer writable. Not blocking — no criterion requires the arm to be
behaviourally non-redundant, and A6 and A8 are met as written.

**2 — correctness risk, and an environment fact. The `ParamName` halves of A6 and A7 are guarded by the
build, not by the tests.** The reviewer's attempt to inject a wrong `ParamName` **failed to compile**:
`CA2208` is escalated to an error in this solution, so `throw new ArgumentOutOfRangeException("other", …)` is
rejected at build time. The `ActualValue` halves are what the tests actually protect, and both were confirmed
live by injecting a wrong `ActualValue` into both arms — exactly two failures. This is where the protection
comes from, not a defect.

**3 — cosmetic. Both new assertions invoke `act` twice.**
`MutationOutcomeExtensionsTests.cs:116-137`. `act.Should().Throw<…>().Which.ParamName…` followed by a second
`act.Should().Throw<…>().Which.ActualValue…` executes `ToResult` twice per test. `.And`, or one `.Which` bound
to a local, expresses the same thing once. Harmless here.

**4 — not a defect; a check the reviewer ran rather than assumed.** Inserting `None` at zero shifts `Success`
from 0 to 1, which would break data compatibility if the enum were persisted.
`grep -rn "MutationOutcome" --include=*.cs src/ -l` returns 12 files, all Domain, Application or Tests, with
no Infrastructure or persistence reference. The enum is a transient return type and nothing stored is
affected.

## Process note from the reviewer, worth carrying

`Copy-Item` **preserves `LastWriteTime`**, so the reviewer's first restore did not trigger an MSBuild rebuild
and a stale injected DLL produced a spurious two-failure run. It touched the file's timestamp and re-ran; the
`837 / 0` result above is from the rebuilt run. This is a new instrument-level trap in this environment: a
restore that is byte-correct can still be measured against a stale binary.
