### B1 (round 1, blocking) -- no test dispatched a newly-guarded command through a real container

Criterion 3 requires each rejection be **reachable through the dispatcher**, proved by a real-container
dispatch asserting `ErrorCategory.Validation`, with at least one on the **non-generic** path. None existed:
`grep -rn "SendAsync" DungeonMaster.Tests/ | grep -i "reorder\|areaoutline"` exited 1. The near-miss,
`ReorderFloorCommandHandlerTests.cs:104`, asserts `ErrorCategory.Validation` but invokes the **handler
directly**, so that category comes from the aggregate's own guard -- it proves nothing about pipeline
reachability.

**Root cause: a defective brief, not defective work.** The orchestrator's dispatch quoted only the first
sentence of criterion 3 and dropped the dispatcher-reachability half entirely, because the Gate 2 criteria
listing had been printed truncated to 190 characters. **T7 built exactly what it was told.**

## Ruling on the `.NotEmpty()` omission -- correct engineering, not under-delivery

`dispatch-and-pipeline.md` §5 says to match the existing area validators' name rules, which are
`.NotEmpty().MaximumLength(100)`. T7 applied `.MaximumLength(100)` only. Every link verified independently:

- `AddFloorCommand` / `UpdateFloorCommand`: `string? Name` -- **nullable**
- `AddAreaCommand` / `UpdateAreaCommand`: `string Name` -- **non-nullable**. The asymmetry is real.
- `AddFloorCommandHandler`: `dungeon.AddFloor(command.Name)`, unguarded; `DungeonMethods.cs:42` is
  `public Floor.Floor AddFloor(string? name)` -- nullable parameter, no guard
- `Floor.cs:50`: `public string? Name { get; private set; }` -- **the domain models an unnamed floor as legal**

Copying `.NotEmpty()` would have made every currently-legal unnamed floor un-addable and un-updatable -- a
behaviour regression dressed as compliance. `Validate_WithNoName_Passes` pins it on both floor validator
test classes. **Criterion 5's substance -- the length limit agrees, no new limit invented -- is met.**

## Advisory findings

1. **Keep the `IsInEnum()` / `NotNull()` rules T7 offered to drop.** They reject inputs the domain
   currently accepts: `PlacedObject`'s constructor guards only `scale`, leaving `Kind`, `Rotation` and
   `Position` unguarded, and `Position` is `= default!` with `CanvasPoint` a record reference type. Both
   enums are plain non-flags enums, so `IsInEnum` behaves correctly rather than misfiring as it does on
   `[Flags]`. Everything newly rejected is already a caller bug. **Net defect reduction at no
   compatibility cost.**
2. Three of the four dispatch tests omit the `DidNotReceiveWithAnyArgs` proof. Not a gap -- the
   `ValidationErrors` provenance argument covers them -- but adding it to the `UpdateAreaOutline` test
   would make the short-circuit explicit on both new-behaviour-registration commands rather than one.
3. `LoadAsync(default, default)` under `DidNotReceiveWithAnyArgs()` is idiomatic NSubstitute but reads as
   if the arguments matter; a comment or the `Arg.Any<>` + plain `DidNotReceive()` form would be less
   likely to be weakened by a later editor.
4. `ReorderFloorCommandValidator` bounds only the lower end of `NewNumber`, documented in the class summary
   as belonging to the aggregate. Correct call -- recorded so it is not read as an oversight.
