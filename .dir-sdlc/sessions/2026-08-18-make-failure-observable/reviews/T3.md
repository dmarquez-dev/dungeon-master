   `DeleteAsync` signatures and `FindAsync([id], ct)` now one argument per line), while the three new
   test methods leave 2- and 3-argument calls inline -- `DungeonWriteRepositoryTests.cs:135` and `:196`.
   The test form matches the file's own unanimous existing precedent (parent lines 42, 64, 87, 108,

   one, so it is defensible as written -- but the diff applies two different rules in one commit. Not
   blocking: §4 is not among criterion 6's enumerated formatting requirements, and `IDE0055` does not
   enforce argument wrapping (build is 0 warnings).

   `DeleteAsync_WithExistingDungeon_ReturnsTrue`** -- same seed, same act, same "row is gone"
   assertion, minus the return-value check. It still compiles and passes (awaiting and discarding a
   `Task<bool>` is legal), and criterion 3 did not ask for its removal, so leaving it is correct here.
   Worth folding into T4's rewrite if that task touches these tests.
