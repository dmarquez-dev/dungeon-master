## THE NAMED GATE ITEM -- validation bypass closure: CONFIRMED CLOSED

T4 left a validation bypass: its non-generic `SendAsync(ICommand, ct)` resolved the handler with no
behaviour pipeline, so `ValidationBehavior` did not run for the ten non-generic commands, bypassing
`UpdateAreaCommandValidator` and `UpdateDungeonCommandValidator`. **Independently confirmed closed**, on
four grounds:

1. **Real container, real dispatcher, real command.** `BuildRealContainer()` calls only
   `AddApplicationServices()` plus two substituted repositories. The test resolves `IDispatcher` and calls
   `SendAsync(command)`. Both commands are plain `: ICommand`, so this enters the exact overload T4 left
   bypassed. **Nothing in either test constructs a `ValidationBehavior` or a validator by hand.**
2. **The `DidNotReceive` assertion is not vacuous** -- the reviewer checked the one thing that looked
   wrong and found it sound. The handlers call `writeRepository.MutateAsync(...)`, not `LoadAsync`, which
   reads as a no-op assertion. But `MutateAsync` is an extension method whose **first statement** is
   `await writeRepository.LoadAsync(dungeonId, ct)` (`DungeonMutationExtensions.cs:30`). So
   `DidNotReceiveWithAnyArgs().LoadAsync(...)` is a true proof the handler body never executed.
3. **It provably fails on `bcb49dc`.** The baseline overload resolves the handler via `dynamic` and never
   calls `GetServices` for any behaviour. There the handler would run, `LoadAsync` would return `null`,
   and the result would be `ErrorCategory.NotFound` -- failing all three assertions. Independently, the
   baseline `IPipelineBehavior<in TCommand, TResult>` is constrained `where TCommand : ICommand<TResult>`,
   so no behaviour could be registered for a non-generic `ICommand` at all.
4. **The closing registration is derived, not assumed.** `DependencyInjection.cs:47-53` registers
   `IPipelineBehavior<TCommand, Result>` <- `ValidationBehavior<TCommand>` for every `ICommandHandler<>`
   found by the scan, and a test asserts exactly one behaviour per command over the assembly-derived set.

## Advisory findings

1. **A1 -- `ScannedTypes` recomputes on every access** (`DependencyInjection.cs:145`): an expression-bodied
   property calling `Assembly.GetTypes()`, filtering and materialising a new `List<Type>` each read. Read
   once in `AddApplicationServices` and once per `ValidateHandlerRegistrations`, so bounded and
   startup-only; a `static readonly` field would express the intent better.
2. **A2 -- `MarkersImplementedBy` called up to three times per type** in the validation loop
   (`DependencyInjection.cs:100`): computed for a `Count == 0` early-exit, then recomputed by
   `MarkerViolationFor` and again by `HandlerTypeFor`. Redundant work in a startup-only path.
3. **A3 -- the test's type filter differs from the production scan's.** The test predicate is
   `type is { IsClass: true, IsAbstract: false }`, omitting the `IsGenericTypeDefinition: false` clause
   `ScannedTypes` carries. Harmless today (no generic request types) but the two should track each other.
4. **A4 -- the marker branch's in-situ hookup is not covered end-to-end.** `MarkerViolationFor` is proven
   to fire and the surrounding `problems.Add`/throw machinery is proven by the missing-handler test, but
   the single line connecting them (`DependencyInjection.cs:112`) is exercised by no test. Residue of an
   unavoidable trade-off -- a real two-marker type cannot live in the Application assembly.
5. **A5 -- `ValidateHandlerRegistrations` is not wired into application startup.** `MauiProgram.cs:123`
   calls `AddApplicationServices()` but nothing calls the self-check outside tests, so the guard runs only
   under `dotnet test`. Not required by any criterion; calling it from a debug-only startup path would
   make a forgotten handler fail loudly at launch too.
6. **A6 -- the invoker cache is `static` and never cleared.** Process-wide, so test-local request types
   accumulate for the life of the run. Correct as written, and the staticness is what makes the
   cross-provider `BeSameAs` proof possible -- deliberate, worth knowing.
