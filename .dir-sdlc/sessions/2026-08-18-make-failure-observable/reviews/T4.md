## The nine rewritten tests -- itemised, and the weakening question answered

Name census (`3b44d91` vs working tree) shows **exactly five method names removed, all five accounted for
by a rename in the same file. No test was silently dropped**; every other file is pure addition.

**Five renamed with inverted assertions -- all five inversions correct, none weakened:**

1. `AddPlacedObjectCommandHandlerTests`: `_FloorNotFound_ReturnsValidationFailure` -> `_WithUnknownFloorId_ReturnsNotFoundNamingTheFloor`. Old asserted `ErrorCategory.Validation`; new asserts `NotFound` **plus** `Error.Contains(floorId)` **plus** `DidNotReceive().UpdateAsync`. **Strictly stronger** -- three assertions where there was one.
2. `RemovePlacedObjectCommandHandlerTests`: `_FloorNotFound_ReturnsSuccessWithNoChange` -> `_WithUnknownFloorId_ReturnsNotFoundAndDoesNotSave`. Old asserted `IsSuccess` + `Received(1).UpdateAsync` -- **the silent success CORE-001 describes, encoded as a passing test.** New asserts `NotFound` + `DidNotReceive()`.
3. Same file, `_ObjectNotFound_` equivalent. **Retains** the pre-existing `floor.Objects.Should().BeEmpty()` state assertion.
4. `UpdatePlacedObjectCommandHandlerTests`: `_FloorNotFound_` equivalent.

**On weakening specifically:** these five dropped an explicit `IsSuccess.Should().BeFalse()` in favour of
`ErrorCategory.Should().Be(ErrorCategory.NotFound)`. That is **not** a relaxation -- `Result.ErrorCategory`
is declared `ErrorCategory?` and is `null` on success (`Result.cs:30`; `Result.Success()` sets only
`IsSuccess`), so asserting `Be(NotFound)` strictly implies failure. §7 asks for precisely this assertion.

**Four rewritten without rename**, `result.Value.Should().BeTrue()` removed -- forced, because `Value` does
not exist on the non-generic `Result`, and the removed assertion **was the always-true `bool` MASTER-088
exists to delete; it asserted nothing**: `DeleteDungeonCommandHandlerTests.HandleAsync_WithValidId_ReturnsSuccess`
(6), `UpdateAreaCommandHandlerTests` (7, retains `area.Name`/`Description`), `UpdateAreaOutlineCommandHandlerTests`
(8, retains `Outline.HaveCount(3)`), `UpdateFloorCommandHandlerTests` (9, retains `floor.Name`/`Notes`).

The helper tests go **further** than §7 required: both `MutateAsync_WithUnknownDungeon_*` assert
`mutated.Should().BeFalse()`, proving the delegate never ran, which the contract did not ask for.

## Blocking finding

**B1 -- T4 wrote to two T5-owned files.** `Common/Behaviors/ValidationBehavior.cs` and
`ValidationFailureCollector.cs` were swept by a CRLF normalisation driven off `git status --porcelain`
rather than a path-scoped list. Blocking **by the standing ownership rule**, which sits outside the
criteria-only bar -- the reviewer records "Criterion violated: none of the twelve." A write into a
concurrent peer's files corrupts silently and is invisible in a path-scoped diff.

Damage independently re-verified as **nil**, twice: by the orchestrator and again by T5's reviewer.
`CollectAsync` still returns `Task<IReadOnlyList<ValidationError>>` (line 29) and still awaits
`validator.ValidateAsync` (line 39); `ValidationBehavior.cs` still has 0 `ValidateAsync` occurrences.

Reviewer's ranked remediation options:

1. **Record the incident and proceed with no code action.** The transform was byte-idempotent and both
   files verify intact, so a revert would be a no-op that risks disturbing T5's uncommitted work. The cost
   is precedent, not corruption. *(evidence: repo)*
2. **Scope the remaining session's normalisation passes to an explicit path list instead of
   `git status --porcelain`.** The porcelain listing is worktree-wide and cannot distinguish a peer's
   uncommitted work from your own; the fix belongs in the procedure, not this task. *(evidence: repo)*
3. **Have T5's reviewer diff those two files against T5's last-known state as an explicit gate item.**
   Cheapest independent confirmation, placed where the ownership lies. *(evidence: judgment)*

**Orchestrator resolution: all three adopted, no revision round.** Option 1 because no code change would
resolve it -- there is nothing to fix. Option 3 was already performed independently by T5's reviewer, which
confirmed the files sound to commit. Option 2 is carried forward as a standing instruction in every
remaining dispatch (T6, T7, T8): **no whole-tree operation driven off `git status --porcelain`; normalise
by explicit path list only.** Recorded for Gate 3 as a process finding. Note the same root cause produced
the orchestrator's own earlier `sed -i` slip -- a whole-tree operation in a worktree four tasks share.
