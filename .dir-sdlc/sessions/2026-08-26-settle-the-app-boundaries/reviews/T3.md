### 1. Criterion 11's rationale is false, and the import it mandates is dead

The written claim falsified: `contracts/app-core-presentation.cs` ~line 44 — *"DungeonDetailPage is the page boundary UIKIT-005 names as the place to map"* — and criterion 11's echo of it. That was true when the contract froze; criterion 12 then drew the boundary at the view model instead, and the two cannot both hold. It moves scoped work: sub-sessions 5b and 5c inherit this contract's shapes and its description of where mapping happens.

**Reviewer's ruling, unhedged: criterion 11 is met, and keeping the dead using was the right call.** The criterion's binding content is its measurable assertion — exactly three files stop, and it names `DungeonDetailPage.xaml.cs` as one of the two that keep it. Removing the using would have made four of five stop and failed the criterion as written. Deviating from a frozen, explicitly-named, measurable assertion because the implementer judged the stated reason obsolete is the unilateral drift that freezing exists to prevent. **The import should still go — as a follow-on, not in this task.** It is dead code with no analyzer enforcing it (0 warnings means `IDE0005` is off), so it will linger silently and mislead 5b/5c into thinking the page is a mapping boundary.

1. **Remove the using in sub-session 5b/5c and correct the contract text in the same change.** One line deleted at `DungeonDetailPage.xaml.cs:11`, plus a note in the 5c contract that the boundary is the view model. Keeps this session's criteria intact and fixes the claim where the follow-on already has the file open. Evidence: `repo`.
2. **Accept the escalation now, amend criterion 11 to "four of five", and have T3 remove the line.** Correct end state one round sooner, but reopens a frozen criterion on the session's last task for a dead using with no functional effect. Evidence: `judgment`.
3. **Leave it and record it on the audit master index as a known dead using.** Lowest cost, but the option that actually lets the false "page boundary" claim propagate. Evidence: `judgment`.
