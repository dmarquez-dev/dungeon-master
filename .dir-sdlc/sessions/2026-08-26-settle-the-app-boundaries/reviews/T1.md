- **The two out-of-glob lock files are not a defect in T1.** `git diff --stat 702ff76` on
  `src/DungeonMaster.App/packages.lock.json` and `src/DungeonMaster.Tests/packages.lock.json` shows
  `+14` and `+7` with **zero deletions**; the full diff contains nothing but three
  `dungeonmaster.app.core` project nodes, each recording only its Domain/Application dependencies. No
  version bump, no hash change, no reordering. `Directory.Build.props` sets
  `RestorePackagesWithLockFile=true`, so criterion 6's mandated `ProjectReference` additions and
  criterion 12's committed lock files cannot both be satisfied while leaving those files untouched.
  The only alternative would be committing a stale lock file, which is the exact failure mode
  criterion 12 exists to prevent. **The ownership glob was drawn one level too narrow.**
- `Directory.Build.props` sets `RestorePackagesWithLockFile` at **line 21**, not line 23 as the
  implementer's report states. An off-by-two in a citation, no effect on any criterion.
- `src/DungeonMaster.App.Core/packages.lock.json` and `src/DungeonMaster.App.Tests/packages.lock.json`
  are untracked and land only if their directories are added wholesale. The git step should confirm
  both are committed — criterion 12's silently-unpin concern only bites at commit time.
- Future sessions that add a `ProjectReference` should include the sibling `packages.lock.json` in
  the same ownership set.
