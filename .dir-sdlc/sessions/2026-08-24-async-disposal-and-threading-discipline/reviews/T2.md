## Advisory findings

1. **Manifest criterion 6 is internally contradictory and should be recorded as superseded, not carried forward.** It requires a catch in `Dispose()`, which criterion 1 forbids adding; criterion 7 is the corrected duplicate. `manifest.json:52` (criterion 6) vs `manifest.json:47` (criterion 1). Recorded here so Gate 3 does not read criterion 6 as unaddressed.
2. **A very narrow undisposed path survives inside the preload's catch.** If `stream.Dispose()` throws after line 76 has already assigned a decoded image, control reaches line 84 and overwrites that non-null entry with `null` without disposing it. This is contract-conformant — `floor-map-drawable.md` §3 mandates storing `null` on a per-entry failure — and the window is vanishingly small, so it is not a criterion violation. Session 6 could harden it by decoding into a local, closing the stream, then assigning. `src/DungeonMaster.App/Graphics/FloorMapDrawable.cs:76-84`.
3. **The Win2D sentence in the preload's catch comment asserts a platform behaviour nothing in this repository observes.** Lines 81–83 state the exception is "raised when the GraphicsView handler is not yet ready". The wording is carried over from the comment it replaced rather than newly invented, and reads as an explanation rather than a test result, so it does not breach criterion 9 — but it is the one place in the file a reader could mistake for observed runtime evidence. `src/DungeonMaster.App/Graphics/FloorMapDrawable.cs:81-83`.
