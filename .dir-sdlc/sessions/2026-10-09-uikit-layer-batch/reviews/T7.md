## Advisory findings

**A1 — the new test file's own XML doc makes a claim that is false for two of its three heights.**
`BookmarkTabShapeNotchTests.cs:67-68` says "At a height of 10, 15 or 19 with the default notch depth
of 10 the unclamped notch would reach or overshoot the top edge." The unclamped notch is 10, so at
height 15 the apex sits at `Y = 5` and at 19 at `Y = 9` — **both strictly below the top edge.** What
is true at 15 and 19 is that the *half-height clamp binds* (notch 7.5 and 9.5, below `NotchDepth`);
only at height 10 does the unclamped notch reach the top. The premise guard's own wording at `:84`
("about the clamped branch") is accurate; the summary sentence is the inaccurate one.

**Orchestrator's note:** this is new prose this session authored, and it is false. **No criterion
covered it** — criterion 6 governs the test *name*, not its doc comment — which is why the reviewer
correctly classified it advisory rather than blocking. That is a genuine gap in the criteria, not a
reviewer judgment to overturn. Carried to Gate 3 with a recommendation to fix it before the merge
rather than defer it, since the session's own standard is that a correction is new prose and gets no
exemption from measurement.

**A2 — no test case covers the rejected alternative's failure mode.** Criterion 1 rejects
`bounds.Height - 1` because `Height < 1` yields a negative notch and inverts the apex outside the
bounds, yet the lowest height exercised is 10. A case at, say, `Height 0.5` asserting
`apex.Y < bounds.Bottom` would discriminate against that specific alternative; **as written, the
suite would stay green if someone later adopted it.** The existing `BeLessThan((float)bounds.Bottom)`
assertion is already the right shape — it just never sees a height where it could bite.

**A3 — the `[Collection]` rationale is broader than the rule it cites.** `:31-35` is correct about
the precedent — `MauiPropertyTypeTests.cs:34-39` does join the collection without injecting
`AppFixture`, substantially for the reason given — but both `AppTestCollection`'s doc comment and
the rule it points at,
`.dir-sdlc/sessions/2026-09-02-app-sub-suite-rebuild/contracts/app-unit-tests-project.md:209-210`,
scope the requirement to classes touching a `Microsoft.Maui.Controls` type. `BookmarkTabShape`
touches only `Microsoft.Maui.Graphics` (`PathF`, `Rect`, `IShape`). The attribute is therefore
**conservative rather than required**, and harmless — joining a collection without injecting its
fixture is valid xUnit — but the file's prose states a sequencing rule the cited source does not
state for this case. No criterion governs it; the judgment call itself is defensible and precedented.

**A4 — the reviewer corrected the ORCHESTRATOR's framing of the `cat -A` hazard, and prevented a
false universal from reaching the register.** The orchestrator had recorded that
`cat -A | grep -c '\^M\$'` "produced a confident wrong zero for a second independent agent", framing
the failure as a property of the *unanchored spelling*. It is not: the failure is
**quoting-dependent**. Measured by the orchestrator on a known-CRLF 54-line file and a known pure-LF
file:

| Form | CRLF file | LF file | |
|---|---|---|---|
| `'\^M\$$'` single-quoted, anchored | **54** | 0 | sound |
| `'\^M\$'` single-quoted, unanchored | **54** | 0 | **also sound** |
| `"\^M\$"` **double-quoted**, unanchored | **0** | 0 | **broken** |
| `"\^M\$$"` double-quoted, anchored | **54** | 0 | sound |

In double quotes the shell collapses `\$` to a bare `$` anchor, which can never match because
`cat -A` emits a literal `$` **after** `^M`. In single quotes grep receives the escape intact and
matches that literal. **So the register must name the quoting, not the spelling**, and
`'\^M\$$'` — robust under both quotings — remains the form to mandate.
