## Advisory findings

1. **Criterion 8's grep pattern is over-broad, and the alias it forced is the worse code.** `MapHitTester.cs:8-9` imports two same-project types by alias (`using AreaItem = DungeonMaster.App.Core.Presentation.AreaItem;`) solely because `using DungeonMaster\.App\.` also matches App.Core's own sibling namespace — the one the frozen contract's signatures require. The reviewer's two rulings: **(1) the intent is met** — no `Microsoft.Maui`, `Microsoft.UI`, `PointF` or `RectF` anywhere in the seven files, App.Core acquired no reference, and `DungeonMaster.App.Core.Presentation` is a namespace inside the same assembly, not the App layer. **(2) The workaround should not stand as the permanent shape.** A plain `using DungeonMaster.App.Core.Presentation;` is better code: all 8 pre-existing alias usings in `src` disambiguate a genuine name clash (`MauiApplication`, `AppDispatcher`, `DomainDungeon`, …), so this is the only alias in the tree used as a grep dodge. T1 satisfied the letter and disclosed rather than deviating silently, which is correct under a frozen criterion — **the fix belongs in the criterion, not in a revision round.** Suggested pattern for future tasks: `using DungeonMaster\.App\.(?!Core\.)`.

2. **Doc rewordings to dodge the same grep are acceptable, and so is usings-before-`namespace`.** `CanvasRect.cs` renders the contract's "`Microsoft.Maui.Graphics.RectF` is unavailable" as "the MAUI graphics rectangle type"; `MapHitTester.cs` renders the `ObjectKindInfo` path as "that type lives in the MAUI App project". Both preserve meaning and were forced by the criterion's bare `RectF` / `Microsoft\.Maui` alternates. Usings before `namespace` matches `TileCoordinateHelper.cs:1-3`.

3. **The contract's ``Was `_field` `` provenance is gone from the docs.** `MapEditorState.cs` replaces every "Was `_selectedFloorId`" / "Was `RectF _popupBounds`" mapping with descriptive prose. Criterion 10 asks for `TileCoordinateHelper` style, which the prose matches better, so not a defect — **but T5 needs that field mapping** and must read `contracts/app-core-editor.cs` to get it. Carried into T5's dispatch.

4. **Criterion 14's literal command cannot pass in a shared worktree.** `git status --porcelain` at `C:\dm-wt\5b` lists 12 modified and 1 untracked path from concurrent tasks. The verification step is unsound whenever tasks share a worktree; scoping it to the task's own globs (`git status --porcelain -- <owns>`, plus a check that no App.Core path outside them appears) would make it checkable. Method-level finding for future manifests.
