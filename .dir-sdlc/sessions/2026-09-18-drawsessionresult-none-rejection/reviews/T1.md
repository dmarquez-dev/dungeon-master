### The A2 exit-code ambiguity, and how it was resolved

The implementer raised it rather than reshaping the run to satisfy the wording: A2 requires the
injected run to "build with exit code 0 and report exactly one test failed", and those cannot both
describe the `dotnet test` **process** exit -- any run with a failing test exits 1.

**The reviewer ruled that "builds with exit code 0" scopes the exit code to the build step**, on the
grounds that the criterion's own verb is *builds* and its surrounding sentence explains the clause
exists to prove no exhaustiveness or `CA1508`-style analyser rejects an added enum member. On that
reading the letter and the purpose do not come apart, so it was resolved rather than escalated. The
process exiting 1 is the necessary consequence of a failing test, not a deviation.

Recorded because the ambiguity was real and a later reader should see which reading was applied.

### 2. The "no switch over this enum" universal holds, confirmed by a second, independent route

The implementer's type-token grep is blind to `switch (result)` on a `var`-typed local. The reviewer
closed that blind spot by censusing the **producer** instead: `PlaceVertex` is the only method
returning `DrawSessionResult`, and `grep -rn "PlaceVertex"` over `src/` (with `/obj/` and `/bin/`
filtered) shows exactly one non-test call site, `DungeonDetailPage.xaml.cs:1471`, consumed by an
`if`/`else if` chain at `:1473` and `:1489` -- not a switch.

Any holder of this type that does **not** come from `PlaceVertex` must spell the type token in its
declaration, and so appears in the first grep. The two populations are therefore complete together,
and they agree. This is the `backlog.md:387` lesson applied correctly: two measurements sharing a
method share its blind spot, so the second route was chosen specifically not to share the first's.
