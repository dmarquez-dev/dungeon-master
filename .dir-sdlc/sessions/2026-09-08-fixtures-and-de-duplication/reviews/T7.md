## The `Queries/` consistency argument — verified causally, and it is genuine

T7 argued that both `Queries/` ranges being unchanged is a cross-check on 4(a) rather than a
coincidence. **The reviewer tested the causal link rather than accepting the correlation:**

- `git grep -n "UnitOfWorkSubstitute" 850a10b -- 'src/…/Queries/*.cs'` → **nothing, exit 1.** Neither
  query class took the rewrite.
- Both cited ranges are **byte-identical between `2603170` and `850a10b` modulo whitespace** —
  `git show <commit>:<file> | sed -n '<range>p' | tr -d ' \t\r'` diffs clean for both. *(Whitespace
  normalisation is required because the suite converted from space to tab indentation between the two
  commits — a formatting change, not a content one.)*
- Contrast: `git grep -l "_unitOfWork.Dungeons" 850a10b -- 'src/…/Commands/*.cs' | wc -l` → **14**, and
  the query constructors at `850a10b` still read `Substitute.For<IDungeonReadRepository>()` — exactly
  the shape the original entry described.

**The ranges did not move because the code did not change, and the code did not change because the
rewrite did not reach those two files.** A real cross-check, not a coincidence read as one.
