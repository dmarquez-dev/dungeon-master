## Advisory findings

- **A1 — the `<remarks>` explains less than XCUT-007 asks for.** `Entity.cs:15-18` and `23-26` name the
  path but not the consequence, so until T2 lands `docs/persistence-contract.md` a reader at the entity
  learns only that a decision exists. The criterion covers the pointer, so not a miss. The reviewer
  offers phrasing that would satisfy both 15 and 17 without the banned identifier: "SQLite has no
  native date type, so the CLR type governs how the value round-trips."
- **A2 — `TestDbContextFactory` is `internal` in a shared file where the contract sketched `private`
  and test-local.** `TestDbContextFactory.cs:10`. Well-argued and not blocked, but it widens visibility
  beyond §8.2's sketch; recorded so a later reader does not read the contract and the code as
  disagreeing.
- **A3 — new test code does not follow coding-standards §4 argument wrapping.** e.g. `UnitOfWorkTests.cs`
  puts 2+ arguments on one line. Matches pre-existing precedent in the same folder
  (`DungeonReadRepositoryTests.cs:71` on the parent commit), and criterion 22 does not cover §4 — noted
  so the divergence between §4 and the test-code house style is known rather than rediscovered.
- **A4 — `UnitOfWorkTests` seeds via `seedCtx.Dungeons.AddAsync(...)`** at lines 52, 92, 125. This is
  the call MASTER-033 removed from production precisely because the keys are `ValueGeneratedNever`.
  Criterion 9 scopes its grep to `DungeonWriteRepository.cs`, so this is outside the criteria; `Add`
  would be the consistent choice in new test code.
- **A5 — the third test is in scope, not creep.** `DisposeAsync_WithoutCommit_WritesNothing` proves
  contract §3.2's row "the unit of work is disposed without `CommitAsync` → nothing is written", which
  is the transaction boundary this task creates. No finding.
