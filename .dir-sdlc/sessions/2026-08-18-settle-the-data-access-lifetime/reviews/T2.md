## Rulings

- **R1 — criterion 2's substitution accepted, but the implementer's reason was wrong.** It cited `9903f40`
  as the parent; T2's parent is `ef0b0b65` (T1's commit), which **does** have `IUnitOfWork`, so the test
  would have compiled there. The substitution is faithful regardless — the only T2 change touching this
  test's behaviour is the comparer argument — and the reviewer reproduced the exact `found 1` failure
  itself. **Met on evidence, not on the implementer's reasoning.**
- **R2 — criterion 4 met, and the second test genuinely discriminates.** The reviewer reinstated
  `.HasDefaultValue(1.0f)` in a copy: `Model_ForScale_DoesNotDeclareAStoreGeneratedDefault` fails with
  `Expected scale.TryGetDefaultValue(out _) to be False, but found True`, while all three round-trip
  theory cases still pass. The criterion's literal words are satisfied by a test that exists and asserts;
  the non-discrimination is an honest disclosure and the burden is carried. See A4.
- **R3 — criterion 12's premise is false and the implementer is right.** The file is tab-indented at
  every line start. INFRA-006 is about XML-doc continuation indent and lambda style, not line-start
  indentation. Both the criterion and coding-standards §1 assert the opposite.
- **R4 — `Kind == Unspecified` leaves criterion 8 met.** The criterion and contract §5.1 ask for the same
  *instant* with `Kind` handled consistently, not `Kind == Utc`. Ticks match exactly and the behaviour is
  documented in the contract doc §2.1. See A1.

## Advisory findings

- **A1 — `DateTime` reads back as `Kind.Unspecified`; the UTC invariant is Domain-only and undefended.**
  The reviewer's probe confirms `Kind=Unspecified` on every read from SQLite. A future
  `.ToLocalTime()`/`.ToUniversalTime()` on a loaded timestamp would silently shift by the local offset.
  `docs/persistence-contract.md` §2.1 states this, but no test enforces it. Worth a backlog entry.
- **A2 — EF tooling `10.0.3` vs runtime `10.0.11`.** Reproduced verbatim in the reviewer's own run:
  `The Entity Framework tools version '10.0.3' is older than that of the runtime '10.0.11'.` Migration and
  snapshot came out correct, so not a defect in the diff, but `dotnet-ef` should be updated before the
  next scaffold. Backlog.
- **A3 — the `Up` rewrite silently skips any non-UTC offset suffix.** `LIKE '%+00:00'` means a value
  stored as e.g. `…+01:00` is left intact and would then fail to parse as `DateTime`. The migration's XML
  documentation explains why that cannot occur for this data set (all values from `DateTimeOffset.UtcNow`),
  which is the right call — noted so the reasoning is not lost if the table is ever fed from elsewhere.
- **A4 — the `Scale` round-trip theory cannot fail.** `[0.25f, 2.5f, 4.0f]` pass identically with and
  without the store default (verified). It documents intent rather than protecting it;
  `Model_ForScale_DoesNotDeclareAStoreGeneratedDefault` is the real guard. A comment on the theory saying
  so would help.
- **A5 — the doc's migration count differs from the commit message it quotes.** `7a4bb2d`'s message says
  "Replaces nine migrations"; `git show --stat 7a4bb2d` shows six removed or renamed. The doc's "five
  deleted plus one rewritten" is accurate and matches the criterion; a one-clause note that the commit
  message's "nine" is itself wrong would close the loop for a future reader who checks. **This is the same
  contradiction the audit's own backlog already carries as a correction to `INFRA-020`.**
- **A6 — the comparer's hash lambda is not null-guarded** while the equality lambda is. EF does not invoke
  it with null on this model (non-nullable property, converter never yields null), so this is theoretical,
  but the asymmetry invites a question later.
