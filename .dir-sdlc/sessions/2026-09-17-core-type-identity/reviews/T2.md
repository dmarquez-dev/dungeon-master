## Advisory findings

No options are attached: `dir-reviewer` supplies ranked options for blocking findings only.

1. **The claimed forced deviation in control (7) is genuine, not a rationalisation — the reviewer checked it
   rather than accepting it.** Collapsing the two receivers to one (`floor.Equals((object?)null)` at
   `EntityEqualityTests.cs:151`) fails the build with `error CS8602: Dereference of a possibly null reference`
   at `(151,27)`, exactly as the in-code comment at lines 141-143 states. Roslyn's nullable analysis marks a
   receiver maybe-null once it has been compared against null, and `TreatWarningsAsErrors` turns that into a
   build failure. Recorded as a **verified, legitimate deviation**; no action needed.
2. **Fact (3) also goes red under the `LastModified`-in-hash injection**, so the hash-mutability defect is
   caught by two facts rather than one. Redundancy in the task's favour, not a defect.
3. **`GetHashCode_AfterAMutationThatTouchesLastModified_IsUnchanged` uses `await Task.Delay(20)`** to force a
   clock tick for the `BeAfter` assertion. It passed on every run, but a wall-clock delay can flake on a
   loaded agent if `DateTime.UtcNow` resolution ever disappoints. Outside this task's criteria.

> **Orchestrator note on advisory 3 — it is larger than the reviewer could see.** The reviewer is handed no
> discipline by design, so it flagged this only as a flake risk. The composed test discipline at
> `disciplines/test.md:33` forbids it outright: *"No sleeping. Wait on the condition, with a timeout, or make
> the operation synchronous for the test."* **The rule and the contract are in genuine conflict here**: the
> criterion requires proving `LastModified` actually changed or the test is vacuous; `LastModified` is
> `DateTime.UtcNow`, so two calls can return the same value; and the discipline's prescribed remedy — make the
> operation synchronous for the test — requires injecting a clock, which contract §3 forbids as a production
> seam. The implementer chose the rule that kept the test non-vacuous, which is the right call, but chose it
> **silently** rather than reporting the conflict. Carried to Gate 3 as a decision, not fixed here.

## Environment findings worth carrying forward

Both cost the reviewer aborted work and both are instrument defects, not code defects:

- **`git show <rev>:<path> > file` and `perl -pe` strip CR in this Git Bash**, producing the LF wall of
  `IDE0055` errors with no mention of line endings. `head -N file > out` preserves CRLF.
- **`sed -n 'Np' file | cat -A` displays lines without `^M` even when the file is CRLF** — a false negative
  that nearly produced a reported line-ending regression that did not exist. `head -N | tail -1 | cat -A`
  shows the truth.
