## Advisory findings

**A1 -- criterion 4's own verification command returns 0.** `grep -cE "^\tpublic static ..."` gives
**0, exit 1**, because ERE does not interpret `\t`; the `[[:space:]]*` form gives **54**, matching the
runtime reflection probe. **The orchestrator adjudicated this directly**, running all three forms in
one shell against one file:

```
grep -cE "^\tpublic static ... =>"            -> 0   (exit 1)
grep -cE "^[[:space:]]*public static ... =>"  -> 54
grep -cE "^\s*public static ... =>"           -> 54
```

The number in the criterion is right; **the command frozen beside it is not**. This is the session's
fourth grep-form defect and the recurrence of a pitfall this project had already written down. It is
also the first case where an **agent reported a command-and-result pair that does not hold** -- the
architect stated it ran the `^\t` form and obtained 54. Correct the command in the manifest so Gate 3
does not re-run it.

**A2 -- the dead-surface claim needs narrowing before it reaches the backlog.** `ThemeFileText` is
confirmed at **zero** call sites outside `ThemeSource.cs`. **`KeyDefinitionPattern` has one** --
`ThemeSourceTests.cs:458` -- which asserts `IsMatch(...).Should().BeFalse()`, a test **of the pattern
itself**, not a consumer. Recording "zero call sites" would put a wrong entry in the backlog. The
orchestrator confirmed, and also found `LegacyTolerantKeyDefinitionPattern` at `ThemeSourceTests.cs:452`
plus a `<see cref>` reference at `ThemeTokenParityTests.cs:328`.

**A3 -- criterion 4's "`DmTheme` declares no public static methods" is true only for the TFM under
test.** `ToPlatform` at `DmTheme.cs:521` is `public static` inside the `#if WINDOWS` block spanning
`:500-541`, so it is absent from the `net10.0` build the sweep reflects over. No effect on the test;
the parenthetical is narrower than it reads.

**A4 -- the class name overstates its contents, and not renaming was right.**
`BindablePropertyDefaultsMatchTokensTests` now holds one fact about a XAML `StrokeShape` literal and
nothing about bindable properties. **A rename creates a path outside `owns`, so doing it unilaterally
would have been the contract violation, not the fix.** Belongs to a follow-on that owns the new path.
The class-level `<remarks>` T9 added mitigates it for anyone opening the file.

**A5 -- the fixture-mutation reason is sufficient, and the reviewer made it sharper.**
`DungeonMaster.App.UnitTests` has no `xunit.runner.json` and no `CollectionBehavior` attribute, so
xunit v2 defaults apply -- sequential within a collection -- and **all four** classes in the assembly
carry `[Collection(AppTestCollection.Name)]`, so nothing can observe the detach window today. The
concrete tripwire is contract **§4.2**: the first class in this assembly that touches a MAUI type
*without* the attribute reopens the hazard. Worth naming §4.2 in the remark rather than the vaguer
"if anything made the collection parallel".

**A6 -- the backup-copy contradiction, with a cost measured during this very review.** T9 flagged
that the dispatch briefs require a byte copy while `dir-shell` §5 forbids one. **The reviewer then hit
the concrete cost itself:** `sed -i` on a CRLF file normalised the whole file to LF and produced ~45
`IDE0055` errors. It restored from a byte copy and did every subsequent injection through a
binary-safe substitution. On a repository with `TreatWarningsAsErrors` and CRLF-sensitive formatting
analyzers, *"git holds the prior state"* is true, but **recovering from it is not free once the file
already carries uncommitted work.**
