## The inert-delta finding -- upheld, and the demonstration itself corrected

T6 reported that the injection **its own criterion prescribed** was inert: shifting `deltas` left all format-4 tests green, because `idDelta` changes only the glyph id and the parser tests that id solely for `!= 0`. It fixed the **fixture** rather than the criterion, adding a segment (`U+0050`, `idDelta 0xFFB0`) whose delta wraps its glyph id to **0**, making it the one code whose coverage a delta shift flips.

**The reviewer upheld the finding and found the demonstration contaminated.** T6's shift form was
`var deltas = startCodes + segmentCountTimesTwo + 2;` — but `rangeOffsets` is **derived from
`deltas`**, so that single edit shifts **two** arrays, not one, and it reddened 3 tests even on the
naive fixture. Applying a properly **isolated** delta shift, with `rangeOffsets` re-anchored:

- **naive fixture: 13 passed, 0 failed** — inert, exactly as T6 concluded;
- **shipped fixture: 3 failed**, including `AFormat4SegmentWhoseDeltaWrapsItsGlyphIdToZeroIsNotCovered`.

So T6's **conclusion was right and its evidence was confounded**, and the reviewer's isolation is the
cleaner demonstration. This is the first time in the session that a *correction* has itself needed
correcting, and it was caught the same way everything else was — by running it rather than reading it.
