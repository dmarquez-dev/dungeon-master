## What made this task's evidence unusually strong

**It refused to let its instrument flatter the result.** The allocation harness is a hand-written no-op `RecordingCanvas`, explicitly **not** `Substitute.For<ICanvas>()` — a mocking framework's call log allocates orders of magnitude more than the subject and would have swamped the signal entirely. The criterion had suggested the mock; using it would have produced a confident meaningless number.

**It declined to assert a byte ceiling.** ~97% of the remaining 17,208 B is `PathF`, which it could not eliminate, leaving 3.6% headroom that would flake. The permanent fact asserts the deterministic *difference* instead. Choosing the harder-to-game assertion over the more impressive-looking one.

**It proved it had looked properly before declining.** Both `PathF` sites are declined with evidence, not assertion: it dumped all 55 public instance members of `PathF` by reflection to establish there is no reset, and found it caches a per-instance `PlatformPath` so it cannot be pooled. The reason is recorded at the sites.

**Measured result:** 24,664 → **17,208 B/frame** with tile offsets present (−30.2%); 17,848 → 17,208 without (−3.6%). Both "after" figures identical to the byte — move offsets are now allocation-free.

## Advisories carried to Gate 3

**A1 — one supporting fact in the report is FALSE, and must not reach the commit message or the audit record.** The report states "`ResetDrawState` and `FinishDrawing` each mutate three collections with **no** `Invalidate()` in the method". **`FinishDrawing` contains `MapCanvas.Invalidate()` twice** at `7a0b506` — once immediately after `GhostAreas.Add(outline)` and once as its final statement. Verified independently by the orchestrator. Only the `ResetDrawState` half holds, and even there both call sites (`:767`, `:805`) invalidate afterwards — `:767` via a guarded `MapCanvas.Invalidate()`, `:805` via `RefreshMap()` whose last statement is `MapCanvas.Invalidate()`.

So `RedrawRequested` closes a **latent hazard**, which is what criterion 3 asked for, but it does **not** fix a stale frame reaching the screen today. Criterion 3 is met regardless — the design call was made and reasoned — but the justification is weaker than the report states, and the commit message was written without this sentence.

**A2 — the permanent allocation fact is relative-only, and narrower than its name suggests.** `MovedAreas_AllocateNoMorePerFrameThanUnmovedOnes` compares moved against unmoved, so it catches only an *offset-conditional* regression. The reviewer confirmed the gap by injecting an **unconditional** per-point allocation into `ToPixel` — a real regression on every frame — and **all 30 tests stayed green**, because both sides of the comparison pay it equally. The implementer's framing is honest about why a byte ceiling was rejected and the choice is defensible; the residual blind spot is recorded rather than changed.

**A3 — the palette seam is a proportionate but real public-surface addition.** `public readonly record struct FloorMapPalette` plus the `Func<FloorMapPalette>` constructor overload widen the App assembly's public API beyond what any criterion asked for. The reviewer judged creating that reachability **the right call over escalating**: criterion 7's escalation clause fires only "if the measurement proves impossible", and it was not impossible — the seam sits entirely inside an owned file, so nothing outside the task was revised. The type must be public for the constructor parameter to be usable, and criterion 8 independently required the per-area `WithAlpha` allocation be addressed, which is exactly what hoisting into a per-frame palette does. **Worth a deliberate confirmation at Gate 3 that the widened surface is accepted, not a change.**

## Criterion 7's premise was false — the session's fourth wrong criterion

The criterion says the measurement "IS reachable" because `FloorMapDrawable` is a plain class. It is constructible — but `Draw` was **not callable**: its first statement read `DmTheme.MapGrid`, which throws without `Application.Current.Resources`, and `Application.Current` cannot be provided in `DungeonMaster.App.Tests`. The implementer measured the failure rather than asserting it:

```
System.TypeInitializationException : The type initializer for 'Microsoft.Maui.Controls.Element' threw an exception.
---- The type initializer for 'Microsoft.Maui.Handlers.ViewHandler' threw an exception.
-------- System.Runtime.InteropServices.COMException
   at Microsoft.UI.Xaml.Input.FocusManager.add_GotFocus(...)
```

`ScreenToCanvas` is reachable precisely because it is the half that touches no theme. The criterion also suggested `Substitute.For<ICanvas>()`, which would have swamped the measurement. So the criterion was wrong twice about how its own evidence would be obtained, and the implementer **created** the reachability it assumed rather than escalating — correctly, since the fix stayed inside its ownership.
