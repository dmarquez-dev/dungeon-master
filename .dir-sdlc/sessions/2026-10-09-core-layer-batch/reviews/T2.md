### A2 -- `SnapAnchor.cs:9` reads "the centre of the cell" (en-GB) for a member spelled `Center`

No criterion addresses spelling register, and the other five files are en-US.

### A3 -- a seventh instrument trap: `sed -n 'N,Mp'` strips CR in this shell

The reviewer's first `sed -n '7,14p' | cat -A` showed `$` with no `^M` on a file that is in fact 61/61
CRLF. **`sed` joins `awk` on the strip-list**; `cat -A` over the whole file is the only safe form. This is
not a finding against the implementer -- it is a session instrument note, and it matters because several
agents have used `sed -n` for reads.

## On the `Write`-damage repair

**Sound, and byte-equivalent to what `Edit` would have produced.** The reviewer measured it five ways on
both repaired files: 17/17 lines CRLF with zero lone LFs; **no BOM** (`head -c 4` gives `6e61 6d65`, the
file starts at `namespace`); **no encoding artefact** -- `tr -d '\11\12\15\40-\176' | wc -c` returns 0, so
not one byte sits outside printable ASCII plus tab, CR and LF, and the same check is 0 on the four
`Edit`-only files; clean termination (`tail -c 3` gives `7d0d 0a`, `}\r\n`); and no whitespace residue
(`grep -c '[ ^I]\^M\$'` = 0 across all six, so blank separator lines are bare CRLF).

**The underlying tool property reproduces and is worth carrying forward: `Write` emits LF here, `Edit`
preserves CRLF.**
